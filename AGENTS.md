# Working in xpd

## Release and build invariants

1. **No unvendored system-header C crates in default builds.** Linux and musllinux wheels cross-compile with `maturin build --release --zig`, where system headers such as `/usr/include/openssl` are unavailable. Any Linux C dependency (including transitive proc-macro build dependencies such as `openssl-sys` via `sqlx-macros`) must be vendored in both `[target.'cfg(target_os = "linux")'.dependencies]` and `[target.'cfg(target_os = "linux")'.build-dependencies]`, or kept behind an opt-in feature.
2. **Keep `CI`, `Documentation`, and `Release` parallel on GitHub-hosted runners.** `CI` and `Documentation` run on `ubuntu-latest` with `mr-boxington` caching (`docs.yml` uses `cache-mode: read` so it never races `CI`). `Release` runs only on `v*` tags and `workflow_dispatch`, building all six wheels (`ubuntu-24.04`, `ubuntu-24.04-arm`, `macos-15`, `windows-latest`) plus sdist in parallel with `PyO3/maturin-action`, `sccache`, `lto = "thin"`, and `codegen-units = 16` in `[profile.release]`.
3. **Never push over a red `CI` run on `main`.** `lefthook` `pre-push` mirrors `CI` (`cargo deny check`, `check_sample_marks.py`, `check_rule_conflicts.py`). Fix any failure locally before pushing.
4. **Ship a release in one push and one signed tag.** Bump `Cargo.toml`, `Cargo.lock`, `.claude-plugin/plugin.json`, and `mcp.json` together in one commit on `main`, then push `main` and the signed tag `vX.Y.Z`. The tag run builds all wheels and sdist in parallel, publishes to PyPI with Trusted Publishing, creates the GitHub Release with attestations, and smoke-tests the published package.
